# ADR-0010: 多网关拓扑管理、真实网关解析与凭据直注策略

## 决策背景

《神仙道》服务端架构采用分布式网络网关体系：包括本服主网关（如 `49.232.196.100:8381`）、仙界跨服网关（`81.70.151.85:8457`）、圣域跨服网关（`82.156.185.37:8360`）以及聊天室网关（`8.138.80.147:19753`）。客户端如何寻址与维系连接关系到系统的通信稳定性与安全风控。

## 架构决策

1. **本服主干优先，跨服按需惰性建连 (Multi-Gateway Topology)**：
   - 系统角色激活时优先且仅建立本服主长连接（如 8381 端口），承载角色登录鉴权、属性同步与关卡体力扫荡等主干活动；
   - 仙界、圣域等跨服玩法会话采用惰性按需建连机制，活动调度触发时才动态拨号，避免持续占用空闲 Socket 与暴露多重风控特征。
2. **静态映射与配置覆盖寻址 (Gateway Resolution)**：
   - 针对已知区服（如 `s813`）建立内部默认网关映射字典，同时支持在 `configs/config.yaml` 中通过 `server_addr` 显式重写或覆盖。
3. **多源凭据直注链路 (Ticket Ingress Pipeline)**：
   - 会话初始化时建立多级凭据获取通道：优先读取配置文件显式参数；未指定时自动探测本地 `user.ini`（由更新器生成的最新动态凭证）进行无缝直注；若皆未就绪则调用 `PlatformAuthenticator` 进行原生 Web 登录换票。

## 结果影响

- **收益**：网络资源消耗降至最低，日常体力挂机无需依赖复杂的跨服多路复用连接；本地开发联调完全解耦，随时可用最新凭据直连实机网关。
- **代价**：当执行跨服专属活动（如仙界矿山、圣域远征）时，需要引入次级网关状态机的生命周期维护。
