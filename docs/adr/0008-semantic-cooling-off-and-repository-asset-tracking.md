# ADR-0008: 业务语义智能熔断与静态资产仓库纳管策略

## 决策背景

在 30+ 自动化玩法高并发长周期运行时，经常会遇到游戏服务器返回的确定性业务状态码（例如“体力耗尽”、“今日次数已满”、“背包空间不足”）。若无策略盲目重试，将造成严重的无效请求甚至触发风控封禁；同时，工程的数据字典（1.5MB `Pieb.db`）与数万条题库需要决定发布与代码仓库管理策略。

## 架构决策

全面确立 **语义智能熔断（Semantic Cooling-off）** 机制与 **静态数据资产仓库全量纳管策略**：

1. **业务语义智能熔断机制**：
   - 区分“确定性业务耗尽”与“瞬态网络抖动”；
   - 遇到“今日次数耗尽”或“活动已结束”，对应 Routine 自动挂起休眠至本日 24:00 重置；
   - 遇到“体力不足”，对应 Routine 挂起休眠至下个体力恢复调度时间点（如 06:00/12:00/18:00）；
   - 单个玩法的挂起不影响调度流水线中其他玩法独立执行，杜绝因单任务受限导致调度死锁。
2. **数据资产仓库全量纳管**：
   - 将 `data/Pieb.db`、`data/answers.txt`、`data/scra.ini` 直接纳入 Git 跟踪管理；
   - 代码库保持自包含（Self-contained），克隆项目即可开箱即跑，摆脱对本地外部文件路径的强制依赖。

## 结果影响

- **收益**：避免无效请求刷屏与风控风险，提升挂机稳定度；资产随工程统一版本化，部署零负担。
- **代价**：Git 仓库体积增加了约 2MB。
