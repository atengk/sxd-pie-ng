# ADR-0004: 集成纯 Go SQLite 引擎复用老版数据字典

## 决策背景

原版辅助（`D:\Software\疯玩神仙道`）沉淀了完备的本地游戏静态数据字典 `Pieb.db`（1.5MB，包含 8,178 项道具、577 个伙伴、424 个 NPC、龙珠与命格数据表）。重构系统需高效获取这些游戏常量以驱动 30+ 项玩法的自动化业务逻辑。

## 架构决策

采用 **无 CGO 纯 Go 实现的 SQLite 驱动 (`modernc.org/sqlite`)** 直接加载并只读查询 `Pieb.db`：

1. **零 CGO 编译依赖**：保持单静态二进制分发优势，跨平台交叉编译无需配置本地 C 编译器（GCC/MinGW）。
2. **完整继承存量数据资产**：直接复用原版沉淀多年的数十张数据表结构与游戏映射关系，避免繁琐且易遗漏的离线手工重录。
3. **只读挂载与只读缓存**：以只读模式（`mode=ro`）连接 SQLite，并对高频静态字典建立内存二级映射缓存，兼顾启动速度与查询性能。

## 结果影响

- **收益**：开箱即用直接拥有原版 100% 完整元数据，后续支持新玩法（如扫荡、背包整理、仙盟商店）可直接查库。
- **代价**：首次加载驱动会引入微量纯 Go 虚拟字节码解析开销，相比纯内存 JSON 体积略有增加（约数 MB）。
