# ADR-0009: 原生平台认证驱动、双轨凭据模型与自动刷新机制

## 决策背景

《神仙道》传统辅助依赖外部独立工具（如 `疯玩自动更新器.exe` 或内嵌 IE 的 `Sxd Assistant Login Tool.exe`）进行平台账号密码登录并向 `user.ini` 写入短期票据。该方案存在强烈的平台绑定与 Windows 进程依赖，跨平台受限且无法实现自动化的全生命周期票据维测。同时游戏网关分为本服主网关与跨服网关，所要求的登录凭据存在主/跨两套不同参数体系。

## 架构决策

1. **原生 HTTP 平台认证驱动架构**：
   - 彻底脱离对外部更新器二进制的依赖，在 Go 内部定义标准 `PlatformAuthenticator` 接口。
   - 首发实现 `FengwanAuthenticator` 驱动，通过逆向分析的平台 Web API 完成两阶段换票（第一阶段调用平台认证接口换取会话 Cookie，第二阶段调用进入游戏跳转接口提取动态授权码 `code` 与时效凭据）。
2. **双轨凭据数据契约 (Dual-Track Ticket)**：
   - 摒弃单一 Token 设计，采用复合凭据模型，严格分离 `MainServer`（本服凭据：`Time`, `Hash`, `Code`）与 `CrossServer`（跨服凭据：`Time1`, `Hash1`），精准对接本服主会话（`Mod_Player_Base`）与跨服业务（`Mod_StLogin_Base`）。
3. **区服标识归一化 (Server ID Normalization)**：
   - 客户端输入区服号（如 `s813`）时，协议前置拦截器依据平台驱动元数据自动派生平台区服全称（如 `fengwanyx_s813`），消除人工配置多余前缀的心智负担。
4. **主动静默续期与被动失败重登**：
   - 建立带 TTL 的 `TicketCache` 缓存机制，在票据过期前（90 分钟主动静默续约）触发换票；若长连接会话捕获到服务端认证失败状态码，立即触发即时失效与被动重登机制。
5. **网关端口寻址策略**：
   - 采用标准游戏端口（默认 `8080`）兜底与角色配置（`ServerAddr`）覆盖机制，兼顾自动化便利性与特殊网络环境需求。

## 结果影响

- **收益**：系统实现真正意义上的纯 Go 独立自治，无需任何第三方执行档辅助即可开箱运行；双轨凭据清晰解耦主服与跨服通信逻辑。
- **代价**：当第三方游戏平台的 Web 登录前端或反爬规则发生改版时，需要在平台驱动层同步维护 HTTP 逆向链路。
