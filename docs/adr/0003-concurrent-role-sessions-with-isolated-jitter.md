# ADR-0003: 基于独立 Goroutine 的角色会话并发与动态抖动模型

## 决策背景

历史 MFC 工具采用单线程阻塞式轮询调度，一个账号网络波动或活动卡死将阻塞所有角色的自动化执行。而在重构版中，需要在发挥 Go 高并发优势的同时，严密防范游戏服务端的频率风控与封禁机制。

## 架构决策

1. **会话隔离 (Role Session)**：以游戏角色（Role）为最小执行单元，每个角色分配独立且平行的 Goroutine，全生命周期维护各自独立的 TCP Socket 长连接与心跳保活。
2. **独立动态抖动 (Isolated Jitter)**：每个角色内部的日常任务队列均内置独立的防封调度器，在操作发包间随机注入 1~3 秒正态分布抖动延迟，模拟真实人类操作节律。
3. **并发解耦**：单个角色的网络断线、重连重试或超时均完全局限于当前会话内部，绝不阻断其他角色的任务处理。

## 结果影响

- **收益**：大幅提高多账号管理吞吐量与网络容错性，实现真正的无阻塞并行脱机挂机。
- **代价**：并发 Socket 数量随角色增多而增加，需在上层实现平滑的心跳与重连节流控制器。
